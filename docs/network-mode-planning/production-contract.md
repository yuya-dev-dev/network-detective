## 共通条件

- 一人称の調査員。各事件に依頼役と運用役を置き、それぞれ仕事上の目的を持たせる。依頼文200–350字、導入8発話以上、解決・再検討各4発話以上。開始前/開始時/構成/証拠/診断/仮説/提出前/解決/再検討/再挑戦と各証拠に40–70字目安の内心。正解や読むべきEIDを内心で教えない。
- 証拠は最初から全部閲覧可能。実通信やコマンドは行わず、diagnosticも既に採取した固定記録。本文・表・ログを省略せず、完成稿単独で実装に移せること。
- 証拠はEID、kind、acquisition=document/diagnostic、source、nodeIds、observedAt（JST ISO8601）を持つ。全資料を2026-10-07 10:30 JSTに整理した設定。本文の観測範囲/取得時刻を明記し、observedAtは収録終端以後。前日資料には日付2026-10-06を明記。機器は同期済み、ログ欠落なしの範囲を限定する。
- 正常要件はプレイヤーに公開する。架空製品の挙動・有効設定の適用範囲・ログ略記も公開し、標準一般の仕様と混同しない。仮説/原因IDを一致させ、各誤答を提出前の証拠で反証可能にする。
- 構成図は縦型概要と拡大詳細を設計。ノードID、物理リンク、境界、アドレス/プレフィックス、機器ポート、通信プロトコル、方向、観測点、文字による経路説明を備える。正常構成図で故障箇所を色分けしない。新しい図操作機能は要求しない。
- 100点=範囲10/原因30/3主張各10/修復10/再発防止10/確認10。正しい主張3、誤主張3以上。全候補で必要証拠件数1か2を表示し、満点集合の件数と一致させる。必須集合は候補間OR、内部AND。本文だけで立証できる代替集合は受理する。
- 必須集合の一部又はallowedSupportingEvidenceIdsだけは5点。無関係だけ0、誤主張0、矛盾がある場合優先0。必須集合＋無関係・非矛盾証拠は10点（最大2枚以内、ユーザー了承済み）。正常対照やノイズを矛盾として罰しない。今回正主張のcontradictoryEvidenceIdsは全て[]。
- 解決=原因/修復/確認正解、主張計20点以上、総計80点以上、critical未選択。再発防止正解だけを解決の追加条件にしない。criticalは危険な修復・予防・確認候補にのみ明記し、選択時点で解決不可。隠れた減点なし。
- 修復/確認は今後の計画。診断記録から修復後に成功したという結果を捏造しない。初動で記録を保全し、必要な正常業務と境界を維持する。
- 各稿に全候補feedback、全証拠の作者役割、3段階ヒント、6段階因果解説、用語辞典、満点/部分点/ノイズ/criticalの採点例を含む。
- 既存11事件の真相・採点を変更しない。DNS切替、SMTP中継、PMTUD、VPN認可、バックアップACL、既存セキュリティ5テーマは繰り返さない。過去問の文章・舞台・数値・図・設問順を置換して制作しない。
