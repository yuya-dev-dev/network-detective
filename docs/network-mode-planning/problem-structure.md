2026-10-07。作者向け、技術テーマを含む。10題の研究を材料にするが、問題や数値を再現する教材ではない。

|材料|問いの構造|ゲームで残す内容|
|---|---|---|
|業務/制約|どの状態なら利用可能か、何を維持するか|依頼と正常要件、別々の仕事を担う人物の会話|

## 5本の配置

|制作ID|主な学習軸|段階の比較|難度/想定時間|
|---|---|---|---|
|NET01|DHCP・mask・ARP・gateway|承認/現行/配布、名前解決/実送出|やや易、20–30分|
|NET02|VLAN・trunk・L2境界|同じSW/上流、物理up/論理通過、境界前/後|易〜中、20–30分|
|NET03|HTTP/1.1・TLS終端・WebSocket中継|普通のHTTPS/切替、入口/APP、外部/内部対照|中、25–35分|
|NET04|CIDR・最長一致・往復経路・状態|/24と/26、往路/復路、A/Bの独立状態|難、30–45分|
|NET05|DSCP・QoS・キュー・品質|境界前/後、無負荷/同時送信、本番/人工対照|中〜難、30–40分|

厳密な難易度昇順にしない。NET04で方向の相関を深くし、NET05は性能条件の読み方に軸を替える。難度と時間は原稿段階の推定で、プレイテスト実測ではない。

既存11事件のシナリオを調べて重複を避けた。初期候補のPMTUDは既存事件にあるため採用しなかった。セキュリティ編の認証/委任/暗号/更新/監視に寄せず、ネットワーク経路と通信段階の説明を中心にする。

## 読解と採点の整合

選択式でも、用語の名前一つでは解決しない。範囲、原因、3主張の根拠、修復、防止、確認を対応付ける。1枚で主張全体が成立するものは必要1、2観測が必要なものは必要2とし、公開文の条件を勝手に短縮しない。合法な代替集合を採点に入れる。根拠の正常対照を異常否定へ読み替えない。

公開正常要件は既知の前提として用いる。設計の値だけでは実測を保証しない主張には現行/実通信を必要とする。ログの結論は示した対象/区間までに限定。特定の製品仕様を一般論として教えない。

素材や設定の「変更があった」だけで真因にしない。有効値、実通過、観測された症状を結ぶ。ノイズは一事件1枚を基本とし、量だけで難しくしない。比較記録や履歴も、意味がある補助/反証資料として置く。

## 会話と図の引継ぎ

主人公の内心は当事者の仕事を受け止め、観測する姿勢を示す。正しいペアや原因を読む前に教えない。導入・解決・再検討を独立会話で書き、修復は未実施の報告段階と分かる表現にする。既存ゲームの下部吹き出しへ移せる長さを保つ。

図は実装用の構造/レイアウト指定まで制作し、SVG資産そのものは今回作らない。概要の短いラベルと詳細の照合値を分け、線種/色の凡例と文字経路を持つ。図の機器/線/ラベルは全部、証拠か推理に役立つものとし、故障位置を先に示さない。

自由記述での説明力、試験の時間配分、科目Bの全範囲の網羅は本作だけでは代替できない。本作は図と記録の比較から理由を説明する練習として設計する。
