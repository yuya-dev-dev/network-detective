## 全稿共通

- 一人称の主人公は調査員。依頼役と運用役の二人にそれぞれ仕事上の目的を持たせる。真相や攻撃者の人格を先に語らせない。
- 依頼文200–350字。導入8発話以上、開始前/開始時/各タブ/提出前/結果/再挑戦の内心。証拠ごとに短い内心1本。内心は40–70字目安、正解を代弁せず比較方法を示す。
- 証拠本文を全文提示し、EID/表・ログ/出所/時刻/取得法 documentまたはdiagnostic/kind/nodeIdsを持つ。時刻はISO8601で原則日付2026-10-05、JST+09:00。前日資料は明記された2026-10-04を用いる。文中の時分秒は明示日付。観測時刻は資料の状態・範囲の時刻で、全件資料は収録終端、複数イベント資料は最後のイベント以後。元イベント時刻は本文、取得は調査へ資料を揃えた時刻。診断は調査時点までに採取した固定記録。
- 全証拠が最初から存在し閲覧順は自由。診断も疑似演出で実通信は行わない。会話やヒントで新しい決定的事実を追加しない。
- topologyはSVG化できるノードID・アドレス・境界・通信矢印・プロトコル・観測点を示す。証拠nodeIdsは実在するノード。概要は縦型で短いラベル、詳細は拡大時と文字の説明。物理経路・認可・署名・ログ転送を別線種で区別し、凡例を文字でも説明する。
- 仮説/原因IDは一致。正解以外は提出前の証拠で反証できる。誤答ごとに何が不足/矛盾するかをEID付きで説明する。正しい一般論を架空の理由で誤りにしない。
- 報告は範囲/原因/3主張と各1–2証拠/修復/再発防止/確認。配点10/30/30/10/10/10、既存の解決条件とcriticalを維持。正しい主張3＋誤主張3以上、各候補必要証拠件数1か2を公開。
- 満点集合は候補間OR/集合内AND。件数表示と全集合の長さを一致させる。本文だけで成立する代替集合を除外しない。必須集合の要素とallowedSupportingは部分点5、無関係だけ0、矛盾優先0、誤主張0。満点集合＋無関係でも非矛盾なら10（ユーザー了承済み、既存コード同様）。具体例を各稿に記す。
- contradictory=[]は今回すべての正しい主張で基本値とする。正常対照は異常事実の否定ではないため、ノイズを便宜的に矛盾証拠へ分類しない。
- 修復は記録保全を含む実施予定。結果会話で未実施の修復/確認を完了したと語らない。削除や回収で流出済み情報をなかったことにしない。
- 3段階ヒント、6段階因果解説、全候補個別feedback、全証拠の作者役割、用語辞典、解決/再検討会話各4発話以上。
- 攻撃者の人名・身元、未観測の漏えい量、悪意は断定しない。実際の秘密値、攻撃コード、実在システムは使わない。証拠内識別子は架空/表示用タグ。
