# 午後セキュリティ問題の構造をゲームへ変換する

作者向けの設計判断。2026-10-06。研究10題から得た共通の骨格であり、過去問の物語/文章/図/数値/設問の再現ではない。

## 比較と理由の骨格

|問題の材料|プレイヤーの判断|ゲームでの表現|
|---|---|---|
|業務背景/要件|何を守り、何を続けるか|200–350字の依頼と正常要件。人物に異なる実務上の目的を与える|
|構成図/役割|どこで何を検証/観測するか|境界、ノード、通信段階、観測点。概要と拡大詳細・文字説明|
|現行設定/変更|要件と実処理が一致するか|設定と承認資料を区別。機器ID/時刻/対象を共通キーにする|
|ログ/診断|何が成立し、何は言えないか|全件の範囲、固定snapshot、正常対照、独立隔離試験を明記|
|理由記述|なぜ他の説明や一般対策では不足か|仮説ノートと3主張への各1–2証拠。因果の段階を保つ|
|対策/手順|今回止める条件と正常継続|修復/防止/確認のカード。記録保全を含む予定として評価|

用語知識だけの四択にしない。選択式へ変換する際も、原因一つだけでは解決せず、根拠と対策を説明できる組合せを要求する。自由記述の表現力や試験時間配分まで再現するものではない。

## 5本を選ぶ基準

候補軸を認証/委任、Web要求、暗号の保護範囲、更新経路、監視相関に絞った。どの稿も『正常要件→実処理→観測→対処』をたどれる一つの中心原因を持つ。既存6事件のACL移設/DNS既存接続/SMTP中継/MTU/VPN対象権限/バックアップ継承をそのまま再利用しない。

|制作ID|学習軸|舞台と仕事の焦点|推理の比較|難度/時間|
|---|---|---|---|---|
|SEC01|認証と外部委任|種苗交換会・受け渡しの連絡先|本人確認/同意/用途審査/利用記録|2/15分|
|SEC02|Webとブラウザ|古書工房・本人が選ぶ届け先|経路/認証/状態変更/意思確認|3/20分|
|SEC03|署名・暗号と信頼|防災訓練・指定先へ段取りを渡す|内容保護/改変検知/区間/保管|2/16分|
|SEC04|更新と出所|港湾検品・未確認を確認済みにしない|承認/実体/出所/実行/業務結果|3/24分|
|SEC05|認証監視|野鳥観測・共有と公開前情報の保護|行/試行/主体/集計/通知/成功有無|3/22分|

難度は混在、概ね後半で相関が深まる。SEC03を中盤の読み直しやすい事件とし、厳密な昇順にはしない。5本でセキュリティ全分野を網羅したとは言わない。新しいAIテーマを無理に入れるより、固定証拠で一意に成立し、既存ゲームで表現できるものを優先。

## データ契約と読みやすさ

主張は正3/誤3、必要証拠数を全カードへ明記。本文一枚で成立する主張を採点都合で2枚へ固定せず、合法な代替集合を認める。公開正常要件もプレイヤーの既知情報として数える。ログ内の原事実と作者の判断を混ぜない。

各資料はタイトル/出所/観測時刻/取得法/nodeIds、text/table/logへの展開内容、短い内心を持つ。未知語は一般辞典へ、事件固有の前提はcontextへ。構成図は境界と経路の違いが推理に役立つ場合だけ詳細化する。カードは短い冒頭・表・必要な注記として読み、長い作者解説を調査画面へ持ち込まない。

会話は当事者の困り事、期限、守りたい仕事を伝える。主人公の内心は観測の仕方とその人への思いを述べ、正解や証拠ペアを言わない。結果会話は修復が未実施の報告段階と分かる表現にする。
